## 上一篇留了个尾巴

上一篇结尾问了一句:续接回来的那个 agent,手里还是不是原来那套工具?

答案其实很直接——`SendMessage` 续接的动作里,没有任何字段能重新指定工具权限。这不是遗漏,是**结构上就不需要**:续接不是重新 spawn 一次,是找回同一个实例接着说。权限这件事,只在"起"的那一刻决定一次,续接只是把已经定好的那套工具接着用下去,没有二次分配的机会。

这就把问题往前推了一步:**"起"的那一刻,权限具体是怎么定下来的?**

## 权限不是自由裁量,是选一个预设套餐

`Agent` 工具有个字段叫 `subagent_type`。它不是一段自由文本,是从一份**预先注册好的枚举**里选一个。选中的那个类型,自带一份**固定的工具子集**——不是"这次派活的时候顺手给它开几个权限",是"选类型的同时,权限已经被这个类型绑定好了"。

具体差异摆开看会很直观。同样是"能不能改文件"这一条,不同类型的答案完全不同:

- 有的类型工具是 `*`——全部工具都能用,没有限制
- 有的类型明确**排除**了 `Agent` / `Artifact` / `ExitPlanMode` / `Edit` / `Write` / `NotebookEdit` 这一串——也就是说,这类 agent 只能读、只能搜、**不能写、不能改、也不能再派生新的 agent**

后面这条"不能再派生新的 agent"值得多停一秒——`subagent_type` 的工具子集里,`Agent` 本身也是可以被排除的一项。换句话说,一个类型的定义可以直接决定"这个 agent 有没有资格再往下派活"。这不是运行时临场判断,是**类型定义时就写死的边界**。

## 类型携带的不只是工具清单,还有一种"心态"

预设类型这个设计,解决的不只是"这个 agent 能不能改文件"这么简单的问题。每个类型还搭配了一段自己的定位描述——比如有的类型明确说自己是"只读搜索,定位代码用的,不做代码评审、不做设计文档核对";有的类型明确说自己是"设计实现方案,不落地代码"。

工具子集和定位描述是绑在一起发的。选类型这个动作,某种程度上是在替被派出去的 agent **预设了一种做事的心态**——一个只有只读工具的 agent,不会去尝试"顺手改一下这个明显的错字",因为它手里根本没有 Edit;一个明确"只做设计不做实现"的类型,即便工具允许,也会在自己的行为边界里刹车。**权限限制和角色定位,是同一个选择的两面**。

## Workflow 里的 agent 调用,用的是同一份注册表

`Workflow` 脚本里起一个 agent,默认拿到的是一套跑 workflow 用的通用工具集。但如果想让某一步的 agent 具备特定角色(比如"这一步要用做代码评审的心态去审"),可以显式指定一个类型——而这个类型**跟 `Agent` 工具里能选的是同一份注册表**,不是 `Workflow` 自己另起的一套。

这意味着"预设套餐"这个设计不是 `Agent` 工具独有的局部机制,是**跨工具共享的一层身份定义**——不管是通过 `Agent` 直接派,还是在 `Workflow` 脚本里派,选中同一个类型名字,拿到的是同一份工具子集和同一种定位。类型注册表本身,是这两条路径背后共用的基础设施。

## Workflow 还多了一层:按需去接,不是一次性塞满

`Workflow` 里的 agent 有一条 `Agent` 工具没有的能力:可以在运行时**按需连到 session 里已经接好的 MCP 工具**,不是在 spawn 那一刻就把所有可能用到的工具一次性塞进去。工具说明用了"schemas load on demand per agent"这样的措辞——每个 agent 自己决定要不要去查、查到了再决定要不要用,而不是一开始就背着一整套可能根本用不上的工具定义。

这跟 [Skills 系列讲过的渐进披露](../skills/02-progressive-disclosure.md)是同一种思路的延伸:Skill 是"先给一句话描述,要用了再展开完整 instructions";这里是"先不接,要用了再去找、再加载 schema"。两边都在回避同一件事——**没用上的信息,不该占位置**。

不过这层按需连接也有一个明确的例外:如果某个 MCP 服务器需要交互式登录才能用,在无人值守的场景(比如定时任务、后台脚本)里,这个服务器可能压根连不上——按需连接解决的是"没用上不占位",解决不了"需要人在场才能连上"这个更底层的限制。

## 这一篇留下的接口

到这里,"权限"这个问题也有了具体答案:类型是预先注册的套餐,工具子集跟着类型走,`Agent` 和 `Workflow` 共用同一份类型注册表,`Workflow` 额外多一层按需接 MCP 的能力。

但权限只回答了"能做什么",还没回答"什么时候等它、什么时候不管"——这是下一篇的问题:前台还是后台。
