## "它说完了"具体指什么

上一篇留下的问题:不管等不等、等多久,最终都要面对"它说完了"这一刻。这一刻具体交回来的是什么东西?

## 默认交回来的,就是它说的最后一段话

一个 agent 干完活,默认没有任何格式要求——**它最后说的那段文字,直接就是交付物**。工具说明里有一句话讲得很直接:

> "Subagents are told their final text IS the return value (not a human-facing message), so they return raw data."

这里有个细节容易被忽略:交回来的不是"一句人话总结",是 raw data——subagent 自己也被告知了这一点,所以它组织最后一段话时,想的是"这段话本身就是数据",而不是"我要说一句让人看得懂的收尾"。这个区分决定了默认情况下拿到的是什么形状的东西:一段散文式的文字,内容可能很扎实,但没有固定的字段、没有可以直接程序化读取的结构。

## 报告是意图声明,不是事实证明

拿到这段话之后,能不能直接信?工具说明专门留了一条提醒:

> "Trust but verify: an agent's summary describes what it intended to do, not necessarily what it did. When an agent writes or edits code, check the actual changes before reporting the work as done."

**"描述了它打算做什么" 不等于 "它实际做了什么"**。尤其是涉及写操作的活——subagent 说"已经把所有旧接口替换掉了",不代表真的全替换完了,需要回头翻一下实际的文件改动,或者跑一遍测试确认,而不是拿到这段话就直接宣布任务结束。

## 想要固定格式,得显式要求

散文式的文字够用,但如果拿到结果之后还要**用代码去处理**它(比如要读里面某个具体字段),纯文字就不方便解析。`Workflow` 脚本里的 agent 调用多一个选项,可以显式要求对方必须交一份符合固定结构的结果,不是随便一段话——不满足格式要求会被拒绝,直到重新交出符合要求的结果为止。

要不要这份"固定格式"的保证,取决于拿到结果之后是**人接着读**,还是**代码接着处理**。前者散文足够,后者才值得多花一步去强制格式。

## 一个具体的陷阱:想直接去读原始输出文件

后台任务完成后,通知里会带一个指向输出文件的路径。这里有个容易踩的坑,工具说明专门区分了几种情况:

- 如果后台跑的是一条命令——直接读那个输出文件是安全的,里面就是标准输出和标准错误
- 但如果后台跑的是一个 agent——**不要直接去读那个输出文件**。它不是一份干净的结果文本,而是这个 subagent 整个对话过程的完整记录(逐条消息的原始记录),体量可能很大,直接读进来会把自己的上下文挤爆

**同样是"后台完成 · 给了个文件路径"这件事,agent 和普通命令的正确取用方式完全不同**——命令的输出文件就是结果本身,agent 的输出文件是过程记录,真正的结果要通过 agent 自己的汇报机制(工具调用的返回值,或者通知本身自带的摘要)去拿,不是靠"打开那个文件看看"这条路。

## 回到"共享任务板不装结果"这件事

开篇留过一个尾巴:任务管理跟结果管理是两套独立的东西。现在能看得更清楚——共享任务板(`Task` 家族)负责的是"谁在干、干到哪一步"这层状态,它的字段清单里没有一个是用来装"干出来的东西"的。真正的结果,不管是散文还是固定格式,都是通过**执行这份活的 agent 自己的汇报机制**送回来的,跟 Task 板上那个状态标记完全是两条线——一条线告诉你"完成了没有",另一条线告诉你"完成的是什么"。
