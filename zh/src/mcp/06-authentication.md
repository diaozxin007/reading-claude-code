# 06 · 认证 · 从一次授权到多服务器免登录

> **TL;DR**:连一个需要认证的远程 MCP server,走的是标准的浏览器授权流程——本地起一个临时页面等回调,拿到令牌后存起来,过期了自动刷新。企业场景下还有一条捷径:员工在公司身份提供方登录一次,后面连的每一个企业内部 server 都不用再单独授权。

[上一篇](05-permissions.md)结尾留了个问题:[02 篇](02-connection.md)提到的"需要认证"这个连接状态,具体是怎么从卡住变成真正连上的。

## 卡住的是"需要认证",不是"连接失败"

回到[02 篇](02-connection.md)的五态状态机:一个 server 因为没有权限访问被拒绝时,不会被归进"连接失败"那一类,而是单独有一个"需要认证"的状态。分开处理的原因很直接——**连接失败通常意味着这次没戏,而需要认证只是"还差一步"**,只要走完授权流程,这个 server 立刻就能从"需要认证"变成"已连接",不需要用户重新配置任何东西。

处于"需要认证"状态的 server,不会在 Tool 列表里彻底消失——它会被替换成一个特殊的、专门用来触发授权的入口,本系列称之为**认证工具**。模型看到的不是"这个 server 现在什么都做不了",而是一个明确写着"调用我来完成登录"的动作,调用之后就能拿到一个跳转授权页面的链接。这个设计让"需要认证"这件事变得可操作,而不是一堵没人能碰的墙。

## 标准流程:浏览器走一趟,令牌存起来

真正的授权走的是业界通行的做法——先在本机临时起一个小型网页服务器等着接收回调,浏览器打开授权页面,用户在页面上确认授权,页面跳转回本机这个临时地址,带着授权结果。整个过程给了几分钟的等待窗口,超时就算这次授权失败,需要重新发起。

拿到授权结果之后,真正代表"你已经登录"的令牌不会明文存在配置文件里,而是存进操作系统自带的密钥管理机制——跟保存密码的方式是同一套,不是 Claude Code 自己另起一个明文文件。令牌本身有有效期,快过期时会在后台自动换一个新的,不需要用户察觉,更不需要每次都重新走一遍浏览器授权。

如果当前环境没有浏览器可用(比如在没有图形界面的服务器上跑),流程会退化成手动粘贴——把授权页面的链接给用户,用户在别的设备上打开、完成授权,再把结果手动粘回来。

## 连了十个内部 server · 只登录一次

企业场景下会遇到一个明显不同的问题:公司内部可能同时提供好几个不同的 MCP server(内部工单系统、内部文档、内部监控面板……),如果每一个都要走一遍完整的浏览器授权,对员工来说体验会很差,每换一个新 server 就要重新登录一次。

Claude Code 针对这种场景实现了一条捷径,本系列称之为**企业免登录**——它依赖公司统一的身份提供方(常见做法就是员工登录企业账号那一套单点登录系统)。具体思路是:员工先跟公司的身份提供方完成**一次**登录,拿到一个代表"你是谁"的凭证;接下来每次要连一个新的企业内部 MCP server,不再重新弹浏览器授权页面,而是拿着刚才那个凭证,在后台悄悄换一张"你有权限访问这个具体 server"的临时通行证——这个换取过程走的是两段标准化的令牌交换协议,全程不需要用户看到任何页面。**用户能感知到的只有开头那一次登录,后面连多少个企业内部 server,都不会再打断他。**

这条捷径不是默认打开的——它需要管理员先做一次性配置(告诉 Claude Code 公司的身份提供方地址是什么),也需要专门的开关明确启用,否则即便某个 server 的配置里写了"走企业免登录这条路",也不会悄悄退化成普通的逐个授权,而是直接报错,提醒管理员这条路径还没配好。这是一个刻意的选择:**要么明确按企业免登录的方式工作,要么干脆失败,不允许在配置和实际行为之间留一个模糊地带。**

## 401 出现在两个不同的时刻

认证问题不一定只在刚连接的时候出现。已经连上、用了一阵子的 server,如果中途令牌失效,再发起一次工具调用同样会撞到权限错误——这时候处理方式跟握手阶段撞到的不完全一样,已经建立的连接会因为这次失败的调用重新被标记需要认证,而不是让这次调用无声无息地失败。不管认证问题出现在握手时还是使用过程中,最终呈现给用户的路径是一致的——回到那个认证工具,重新走一遍授权。

一个 server 认证通过之后,前面几篇讲的都是"调用一个工具"这条路径——模型主动发起,server 执行,返回结果。但 MCP 声明的能力不止 tools 一种,[开篇](01-intro.md)提过的 resources 和一种还没展开的能力——server 反过来向用户要一点信息再继续——分别是什么样子。下一篇 [Resources & Elicitation · 从只能调用到能读能问](07-resources-elicitation.md) 从这里接着讲。
